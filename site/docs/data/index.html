What the plugin sends, and where it goes

The plugin is called Rune Advisor Export. It has one permission, httpAccess, and one address it talks to: https://api.runeadvisor.com. This page lists everything that leaves your computer with the current version. The same list can be read in the plugin's own code, which is written to be read.

When anything is sent

  • Nothing is sent until you paste a token into the plugin's settings and the API accepts it. Without a token the plugin does nothing.
  • A token covers the whole computer. The game keeps a plugin's settings per computer, not per login, so a saved token sends every character played in that game client there, whoever is playing. On a shared computer, tell the others or remove the token when you finish.
  • After that it sends your character's full state once per login, and then only what changed, at most once every few seconds while things are changing (the API sets the pace; 10 seconds by default).
  • After a game update the plugin may also upload the game's own quest and achievement definitions that changed (see below). That is game data, not data about you.

What this version does not read or send

  • Anything about other players: trade screens, other characters, friends or clan lists.
  • Chat of any kind.
  • Where your character is, what you click, or which keys you press.
  • Your Jagex account, login name, email address or anything else about you outside the game.
  • Shop stock or any other item list that is not your own storage.

The server cannot ask the plugin for more. It may tell the plugin how often to post, to stop (a revoked token), and which of the game's quest and achievement definitions it lacks; it never chooses which player data is collected. Adding anything to the list above takes a new plugin version, which Jagex reviews. A later version may send more (the privacy policy names what is being considered); this page changes first.

Game definitions after an update

The plugin works out what to send from the game's own quest and achievement definitions. When a game update changes them, the first plugins to notice upload the changed definitions (names, requirements, descriptions: the same for every player) so the server can decode posts again without a new plugin release. They are game data, not data about you: once checked (by the operator, or because enough other accounts sent exactly the same) they are used for every player and to develop the planner, whether or not you allow analysis, and they are kept after the account that sent them is deleted.

What stays on your computer

The plugin stores three things in the game client's plugin storage: your token, the posting pace the API last asked for, and the last state the API acknowledged (so the next login can send only changes). Removing the token in the plugin's settings, or revoking it on the account page, stops all posting.

What the server keeps

  • The latest state of each character, with the time of the last post. No history is kept today; the server may later keep the changes the plugin already sends as one.
  • For the account: a random id, the day it was made and the day it was last used.
  • For each token: a hash of the token, its first six characters, your label for it, what it may do, the days it was made and last used, and which of your characters it has posted for (with the day of the last post), so the account page can show which token belongs to which plugin.
  • For each character: whether, and since what day, you allow its data to be analysed to improve the planner (off unless you turn it on in the plugin's settings or on the account page; nothing more is sent either way).
  • No email address, no name, no password. The account key itself is not stored, only a hash of it.

Like any web server, it also sees the internet address a request comes from. How long that and everything else is kept, who can see it and how to delete it is in the privacy policy.

Who can read a character's state

Someone holding a read token of the account that the character's plugin posts to: normally only your own planner. You can give a group mate a read token limited to one character. A plugin's own token (submit) cannot read anything back. See accounts, keys and tokens.
